# OWASP Top 10:2025 in aisoft-backend and base-web

A map from each category to where to look. It lists what to inspect, not confirmed vulnerabilities, except where an item says it was observed at the reference revision (`aisoft-backend` `5ebe06c7`, `base-web` `d3d0e0b1`). Re-verify before relying on an observation; the code may have changed. Do not run any check against production or real data.

| Category | Where to look | Observed or to verify |
|---|---|---|
| **A01 Broken Access Control** | BE: `@Authorization()` on every controller; `SystemRoleGuard`; `DataPartitionGuard` and the partition scope in queries; `FileService.accessFile` scopes; `@InternalController` and `GwGuard`. FE: route `access` in `config/routes.ts` and `src/access.ts`. | Observed: `SystemRoleGuard` allows a route with no declared roles, and `data-process` endpoints declare none, so any signed-in user can call them. `FileService` has a `TODO` for read authorization. FE route access only hides UI. Verify each new endpoint for guard, role, owner, and partition. ([BE auth](../../../backend/nestjs/references/authentication.md), [FE access](../../../frontend/umi-max/references/routing-access.md)) |
| **A02 Security Misconfiguration** | BE: Multer and upload limits, CORS and HTTP setup in `config/http-app.ts`, Swagger exposure, config defaults. FE: `config/config.ts`, `ip.ts`, Dockerfile and Nginx config. | Observed: `app.enableCors()` is called with no options (any origin); JSON and form bodies accept up to 50 MB; no upload size limit in the Multer options; `firstNameField` and `lastNameField` in `config/configuration.ts` read the `SSO_EMAIL_FIELD` variable by mistake, so their env overrides do not work as named; the FE Dockerfile installs without `yarn.lock`. Verify what is exposed in each environment and which defaults ship. |
| **A03 Software Supply Chain Failures** | Lockfiles (`package-lock.json`, `yarn.lock`), CI build steps, base images, build secrets (the BE build passes an npm token as a build secret). | Verify dependencies come from the lockfile in CI and images; check for new dependencies in a diff. The BE `README` and FE image build differ from the lockfile. |
| **A04 Cryptographic Failures** | BE: password hashing (`createUserPassword`, `bcryptjs`), JWT and JWKS verification in `SsoService`, TLS options for Redis, secrets in config. FE: tokens in `localStorage`/`sessionStorage`. | Observed: passwords use `bcryptjs` with cost 10 (confirm this meets current policy). The FE writes `partitionCode` and table settings to `localStorage`; lines that stored `token` and `refreshToken` are commented out, so confirm where the session token now lives before assuming it is not in browser storage. Verify algorithms and parameters from code, not from comments. |
| **A05 Injection** | BE: Mongo query operators built from request input (`condition`/filters passed to repositories), raw SQL in `data-process`, template or string concatenation in queries. FE: `dangerouslySetInnerHTML`, `href`/`window.open` from data. | Verify that user-supplied conditions cannot inject operators the caller should not have; check string-built SQL. FE: use `sanitizeObject` and `src/utils/security.ts`. ([UI utilities](../../../frontend/umi-max/references/ui-utilities.md)) |
| **A06 Insecure Design** | Trust boundaries: internal vs user-facing endpoints, multipart upload completion, import flow atomicity, batch operations with no dry-run. | Observed: multipart completion does not check the caller is the author; imports are not atomic; `data-process` has no dry-run. These are design questions for the owner. ([files](../../../backend/nestjs/references/files-and-imports.md), [batch](../../../backend/nestjs/references/settings-and-batch-data.md)) |
| **A07 Authentication Failures** | BE: `JwtAuthGuard`, `JwtSsoGuard` (Keycloak JWKS), session handling in `auth`. FE: OIDC flow in `app.tsx` and the login pages. | Observed: `SsoService.verify` calls `jwtVerify(token, JWKS)` with no `issuer`, `audience`, or `algorithms` options, so those claims are not checked beyond the signature against the JWKS; a failed verification logs the error object to the console. The JWKS is cached in Redis for 4 seconds. `JwtSsoGuard` is commented out of `Authorization()`, which uses `JwtAuthGuard`. Verify which guard protects each route, and revocation. |
| **A08 Software or Data Integrity Failures** | Uploaded content type and recompression, imports of spreadsheets, CI artifacts and image tags, unsafe deserialization. FE: `utils/socket.ts`. | Observed: `src/utils/socket.ts` connects to a hard-coded external host with the stored token at import; do not import it. Verify uploaded files are checked by content, and that import rows are validated. |
| **A09 Security Logging and Alerting Failures** | BE: `AuditLogInterceptor` and the audit queue, error filters, `BaseLoggerModule` (registration commented out). FE: console output, Sentry. | Observed: audit jobs are removed after three failed attempts, so a failed audit write leaves no record. Verify that logs omit tokens and personal data and that security events are recorded. |
| **A10 Mishandling of Exceptional Conditions** | BE: error filters and `ApiError`, unawaited promises (for example push sending), queue failures. FE: Axios response interceptor, empty and error states. | Observed: `OneSignalService.sendBatch` and `sendNotification` are called without `await`, so failures are unhandled rejections; `MinioService` only logs bucket errors. Verify failure paths return a safe error and do not hide the failure or leak internals. |

## Using the map

Pick the categories relevant to the diff, inspect the listed places, and record findings with location, condition, impact, and mitigation. Report an observation as a finding only after re-checking it in the current code. Findings about the project (rather than the method) go to the owner, not into this skill.
